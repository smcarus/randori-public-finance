# Randori Municipal Finance

One codebase, three versions: a web app (installable, works offline), a macOS desktop app (Electron) and an Android app (Capacitor). All three run the same `web/` files and the same calculation engine.

**Illustrative only.** Every figure is for "Town of Example", a hypothetical Massachusetts town. Nothing here is advice to any town or issuer. Randori Resources' municipal advisor registration is pending.

## What's inside

| Tab | Source | Status |
|---|---|---|
| Tax bill | M-06 School Building, M-07 Debt Exclusion Impact (Planning Models v1.0); DLS Tax Rate Options (commercial shift) | Tested: 630 values against the workbook |
| Capital plan and debt | M-08 Capital Plan v1.0; DLS maximum borrowing terms (Aug 11, 2017) | Tested: 330 values against M-08 |
| Five-year forecast | DLS Financial Forecast template layout; DLS levy limit method | **Draft model, sample figures, not in the Model Inventory.** Only the levy limit is tested (5 values) |
| Budget calendar | DLS Budget to Tax Rate Recap Calendar template | Dates shifted from the template |

Bond payments are also checked against the DLS Debt Service Calculator (12 values). Source templates: `/mnt/project-files/inputs/ma-municipal-templates/`.

## Layout

```
web/            the app: index.html, styles.css, engine.js (all math), taxbill.js, modules.js, sw.js, manifest, icons
tests/          node tests + expected values; *.py scripts regenerate expected values from the workbooks with LibreOffice
electron/       macOS desktop shell (main.js)
android/        Android Studio project generated by Capacitor
scripts/        build.mjs (web/ -> dist/ and the one-file page), serve.mjs (local web server)
```

## Everyday commands

You need Node.js 20 or later (`brew install node`).

```
npm install          # once
npm test             # all calculation tests; must pass before any release
npm run serve        # web version at http://localhost:8080 (install it from the browser menu)
```

## macOS app (build on your Mac)

```
npm run mac:dev      # opens the app in a window
npm run mac:dist     # tests, then builds release/Randori Municipal Finance-0.1.0-arm64.dmg (and x64)
```

The build is unsigned. The first time you open it, right-click the app and choose Open. Signing and notarizing for other people needs an Apple Developer ID ($99 a year).

## Android app (build with Android Studio)

1. Install Android Studio (it brings the Android SDK and Java).
2. `npm run android:sync` copies the latest web build into `android/`.
3. `npm run android:open` opens the project in Android Studio. Use Run to install on a phone or emulator, or Build > Build APK(s).

A Play Store release needs a signing key (Build > Generate Signed Bundle) and a Google Play developer account ($25 once).

## Changing the app

1. Edit files in `web/`. Put calculations in `web/engine.js` only, with the source cell or DLS line in a comment.
2. Add or update tests in `tests/`. If a workbook changes, rerun the matching `tests/*.py` script, then `npm test`.
3. `npm run build`, then rebuild whichever versions you need. `dist-single/randori-municipal-finance.html` is the one-file page that gets republished to the link above.
4. Record model changes in the Model Inventory (WSP Appendix A, 2.4) with the new version.

## Known gaps

- M-08 does not compound new growth at 2.5% the way the DLS levy limit worksheet does. The Capital plan tab keeps M-08 v1.0; the Forecast tab uses the DLS method. Fix in M-08 v1.1.
- M-06 School Building tab: row 30 column headings are shifted by one from column J on (labels only).
- Not built yet: cash flow (DLS Cash Flow Forecast tool) and financial indicators (DLS indicator template).
- Fonts load from Google Fonts when online; offline, the app falls back to system fonts.
